# AoR 360 Consumer Crosswalk Audit

**Scope:** read-only static audit of the 360 Age of Rebellion Core Rulebook talent-tree positions in the P244 + WIP5 working tree. No source or tests were changed or run for this audit.

## Source authority and limits

The official source authority identified in Drive is **Star Wars - Age of Rebellion - Core Rulebook.pdf** (Drive file ID `1w2M6f7R_dzaaHk6Q6R8Y7TIqAYM2MJIq`). Catalog node metadata names `Star Wars - Age of Rebellion - Core Rulebook` and stores a printed page per node. The table preserves those page references as recorded in the catalog. This pass did not extract and compare every talent description against the PDF; source-page attribution and rule-text semantics therefore remain pending individual PDF review. No web or secondary source was used.

## Counts and disposition

- Catalog positions: **360** across **6 careers / 18 specializations**, with **165 distinct source talent names** (per the existing catalog inventory).
- Alias registry entries: **161**. Catalog inclusion in `AOR_RUNTIME_MECHANICAL_TALENTS` is a shared name-level flag, not proof each occurrence has an independently verified effect.
- Production source contains many exact source-name/runtime-key references, but those are name-level links. `sourceBackedTalentRank` validates purchase records against node IDs and source names before exposing canonical ranks; it does not establish that each slot’s printed effect is semantically implemented.
- Static test-source search found exact node-ID mentions for **10 / 360** positions and broader source-name/canonical-key mentions for **290 / 360**. Exact-ID mention alone is not full proof: it may assert catalog presence, purchase/path validity, or a single effect without testing printed semantics, consumer outcome, UI interaction, save, and reopen together. Tests were not run.
- **Certified individual positions: 0 / 360. Every position remains `PENDENTE`.** The full source → runtime → consumer → UI/controller → persistence/reopen → individual evidence chain is not demonstrated for any complete row by this audit.

## Shared implementation path (structural evidence only)

- **Catalog/mapping:** `app/src/main/assets/vtt/js/expansion/aorTalentTreesData.mjs` carries slot ID, career/specialization, source and UI names, row/column/cost, and source book/page. `aorTalentRuntimeAliases.mjs` maps source names to canonical keys; `aorProgressionIntegration.mjs` marks entries mechanically active by `originalName` membership in a shared list.
- **Ownership/purchase:** `app/src/main/assets/vtt/js/rules/talents.mjs:17-39` limits an AoR tree to an owned specialization; `:150-188` handles eligibility and purchase, storing node ID, source name, source metadata, career/spec, cost, and choice. Immediate effects are handled in the generic switch at `:58-130`. `sourceBackedTalentRank` at `:232-243` verifies node-ID/source-name authenticity for rank consumers.
- **Controller/UI:** `core/controller.mjs:1299-1307` exposes tree/eligibility/purchase and commits `CHARACTER_UPDATED`; `core/uiBridge.mjs:953-968` forwards it; `:1143-1144` returns trees and eligible slots for owned specializations; `ui/app.mjs:1305` calls `game.buyTalent` and rerenders. These are shared pathways, not 360 row-level UI interaction evidence.
- **Persistence:** `core/storage.mjs:21-32` JSON-saves and reloads state; `core/controller.mjs:574-579` saves after commits, and `:1302-1307` is the generic purchase commit. This is not per-position save/reopen evidence.
- **Representative tests:** `tests/uae-p130-aor-expansion-integrity.test.mjs` covers all 18 tree shapes, one sample purchase, path unlocking, and JSON restoration; `tests/uae-p135-aor-mechanics-and-persistence.test.mjs` checks the 360 catalog count and a set of 15 named mechanics with JSON restoration. Later focused tests through P179 cover additional named mechanics. No test found in this static pass proves all 360 rows through the live UI and storage reopen path.
