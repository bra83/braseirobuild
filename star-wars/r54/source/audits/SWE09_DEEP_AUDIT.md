## 2. Current implementation surface (not certification)

`jewel-of-yavin` is registered as EotE/MIXED and declares three episodes. The primary graph has 15 scene nodes: Port Town → Market Row → Shen contract → Cloud City prep → race prep/race/aftermath → gala → bank → vault → pursuit → either empty-handed exit or jewel epilogue. It exposes scene narration, visible NPC IDs, generic checks, choices, status, encounter hooks, rewards/archive, and a check-history list. Most of Episode I is a single path; the base graph does not model the book's free-form investigation as a clue/lead ledger.

Many focused mechanics were added outside that 15-node graph. The implementation includes separate modules for Grand Prix/auction adjudication; bank slicing, G-100, tools, evidence and settlement; escape bomb/impact/custody/boarding; the Arrow-7 chase/turret; Arend's holdings/property/patrols; Wing Guard/pursuit response; Holo-Park landscape/effects/factions; XP rewards; and world aftermath. A number have controller/UI routes, serialized operations/receipts and persistence tests. This is meaningful implementation work, but the audit found no single evidence crosswalk that proves every published branch is mapped correctly through source → deterministic operation → UI/controller → saved/reopened state.

The primary graph's `adjudicateJewelOfYavinCheck` accepts a boolean `success`, appends a check record and raises the alarm on selected failures; it does not itself prove an actual EotE dice pool/result. More recent separate operations do roll real dice for selected mechanics. Keep those authority boundaries explicit: RAG, suggested actions, scene text and narration may present source/context but must not decide checks, choose branches, create combat results, award items/credits/XP, or mutate flags.

Tests inspected (not rerun during this read-only audit) include `uae-p183-jewel-longarm-pdf-branches.test.mjs`, `uae-p184-jewel-race-auction-pdf.test.mjs`, and the later focused files `uae-p192-jewel-bank-table-completion.test.mjs`, `uae-p193-jewel-wing-guard-arrival.test.mjs`, `uae-p194-jewel-g100-black-box-evidence.test.mjs`, `uae-p195-jewel-live-g100-droid.test.mjs`, `uae-p196-jewel-g100-official-nobodys-fool-muscle-assist.test.mjs`, `uae-p202-jewel-impact-goons.test.mjs`, `uae-p203-jewel-long-extreme-falls.test.mjs`, `uae-p204-jewel-companion-impacts.test.mjs`, `uae-p222-jewel-episode3-xp.test.mjs`, `uae-p227-jewel-custody-transfers.test.mjs`, and `uae-p228-companion-jewel-boarding.test.mjs`. ## 4. Cross-cutting findings

1. **The base graph is not the adventure's source-complete route graph.** Fifteen nodes cannot stand in for the book's non-linear research, planning, seven-leg race, five-hour gala, bank operation, museum heist and multiple getaway decisions. Supporting modules address selected mechanics but do not establish a connected, replayable campaign.
2. **Provenance is split across comments/tests, not a complete claim ledger.** `SOURCE` in `jewelOfYavin.mjs` lacks edition/hash/page refs; many checks/nodes have no page citations. Some module comments cite `SWE09` pages, but that is not enough to show which exact claim, table row, branch, stat, or consequence they implement. Add a page-exact source manifest linked to each in-game operation.
3. **Check authority varies by subsystem.** The primary adventure accepts boolean check outcomes; focused race/auction/bank/impact mechanics contain more deterministic dice/receipt paths. Identify the actual deterministic executor for every check and prevent RAG, GM narration or suggested-action selection from directly granting source-defined effects. Record source rolls and resulting symbols before applying consequences.
4. **UI and persistence proofs are uneven.** Focused tests assert UI/controller/bundle wiring for some branches and reopen particular receipts. A function's existence or serialized data is not proof of user accessibility or complete campaign continuity. Need end-to-end runs from existing-saves and fresh starts through each meaningful branch, UI-visible proof, at least three independent restores, and rollback/duplicate-action checks.
5. **Source visuals remain relevant.** Source maps (museum, race course, Holo-Park) and printed stat blocks should be inspected visually before transcription; OCR/extracted text can omit layout, exact table cells and footers. Do not certify maps or mechanics from regex matching.
6. **Rules boundary.** Use the relevant EotE Core rules for general opposed tests/combat but preserve SWE09-specific options and adjudication exactly. The adventure rules module may own deterministic application; RAG/narrator may retrieve/cite only. It must not roll, interpret ambiguity, or mutate flags, clock, inventory, credits, XP, wounds/strain, NPCs or encounters.
