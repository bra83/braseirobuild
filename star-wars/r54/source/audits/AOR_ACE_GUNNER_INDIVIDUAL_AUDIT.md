## Source verification and a provenance defect

The specified Drive file, ID `1w2M6f7R_dzaaHk6Q6R8Y7TIqAYM2MJIq`, is the 466-page English Age of Rebellion Core Rulebook. The Gunner tree is **printed page 68** (PDF physical page 69); the printed page footer is visible on that page. The preceding printed page 67 is the Ace: Driver Talent Tree. The PDF SHA-256 downloaded to scratch for this read-only source check is `25087E5B43C289EF556A365EEC1177123055DFB75C3ECF03481CD66044CACE50`.

The recovered `expansion/aorTalentTreesData.mjs` records `source.printedPage: 67` for all 20 `ace:gunner` nodes, although the official Gunner tree is printed p.68. That is material: `rules/talents.mjs:167-185` copies each node's `source` into its persisted `talentPurchases` record. Thus a purchase made through the current tree stores a false page citation. The node names, positions, costs, and connections match the official p.68 layout on visual inspection, but saved source provenance does not. This alone keeps each complete slot chain PENDENTE.

## Purchase, UI and persistence route common to the tree

- Tree catalog and source records: `expansion/aorTalentTreesData.mjs` (`AOR_TALENT_TREES`; line 1 is generated/minified) and `expansion/aorProgressionIntegration.mjs:1-18`. The latter exposes all source slots for purchase and marks mechanical coverage from name lists; that flag is not itself effect proof.
- Purchase: `rules/talents.mjs:167-185` validates tree ownership, unlock, unpurchased slot, XP and required choices; it records `nodeId`, source, cost, career and specialization. `core/controller.mjs:1299-1305` delegates talent buys to this rule module and commits CHARACTER_UPDATED. `core/uiBridge.mjs:965-968` exposes `buyTalent(nodeId, options)` to the UI.
- Persistence: controller commits save through `repository.save`; `core/storage.mjs` validates on save and migrates/validates on load. Relevant node-level reopen assertions are cited above where found, but most existing tests build characters via name helpers or test serialization rather than reopening through the actual node ID.
- Source-backed ranks: `rules/talents.mjs:207-241` counts purchased slots against the source tree node ID/name and canonical alias. This prevents display labels alone from granting rank, but the global name aliasing is not sufficiently specific for the `FIRMEZA`/Brace collision identified above.

## Findings and required repair evidence

1. **Printed-page citation is off by one.** All Gunner node records currently say printed p.67; official p.67 is Ace: Driver and official p.68 is Ace: Gunner. The purchase pipeline copies the bad source value into owned talent receipts. Correcting source metadata is required before any node can have an unbroken source-to-persisted-record chain.
2. **Brace is mapped as Grit.** Official Gunner Brace slots R2C2 and R4C3 use recovered original key `FIRMEZA`. Global mapping `FIRMEZA` → `GRIT`, plus the immediate-effect list and purchase handler, gives each slot +1 strain threshold. It does not implement Brace's next-action environmental setback reduction. Both node chains are PENDENTE and should not be treated as mechanically active for the printed effect.
3. **Only selected Gunner effects have complete-looking integration tests.** P165 is a good end-to-end template for the two Overwhelm slots and Debilitating Shot: it checks attack condition, spends actual Advantage, checks changed vehicle state, restores the repository and inspects UI/bundle exposure. P160 similarly covers Spare Clip and Heroic Fortitude; P137 covers first-rank Durable and True Aim; P170 covers Jury Rigged; P176 covers Exhaust Port. Most tests do not pin the individual node IDs and source/page stored in the purchase receipt, and none fixes the p.67 provenance defect.
4. To clear this audit, correct per-node source attribution (Gunner p.68), disambiguate Brace from Grit in the source-to-runtime mapping and implement the environmental setback consumer; then add/run per-node purchase → exact effect → UI/controller → save/reopen tests for the slots/ranks not covered above. Keep PENDENTE until those links are evidenced.
