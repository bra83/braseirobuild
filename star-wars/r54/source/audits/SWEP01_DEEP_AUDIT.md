# SWEP01 - Under a Black Sun: source-led deep audit

**Audit status:** `PENDENTE`  
**Scope:** Compare the Drive PDF for *Under a Black Sun* (SWEP01) with the recovered Star Wars R54 source code, player-facing runtime, save/reopen path, and existing adventure-specific tests. This is a read-only audit; it does not certify any page, scene, rule, or adventure.

## Source identity and page convention

- **Drive file:** `Under a Black Sun.pdf`; Drive file ID `1UI9JILrFoRIYv0FNh_ZhHNFmCEFWIIVZ`; MIME `application/pdf`; 119,107,001 bytes.
- **PDF metadata:** title `Under a Black Sun`; author Fantasy Flight Games; copyright 2013 Lucasfilm/FFG; product code **SWEP01**; print ID `1733JUN13` (PDF physical page 2). SHA-256: `B98C80962B3B721FCB8D32DA19DBE31E14099839C9832A6061D5D2C25680548B`.
- **Page mapping:** The 40-page PDF’s adventure starts on physical/printed page 18. From that point the PDF physical page number matches the printed footer number, through printed page 39. Cover is physical page 1; credits are page 2; rules and pre-generated characters occupy pages 3–17. Adventure overview is p.18, Episodes I–III span pp.19–38, and the epilogue is p.39. Page 40 is back-cover marketing copy.
- **Source handling:** PDF was read from the exact active-adventure Drive inventory record and downloaded to the task scratch area for extraction. It is not in the project tree or Git.

## Cross-cutting implementation and authority findings

1. **Source citation granularity is missing.** `UNDER_BLACK_SUN.source` contains title, system, `productCode: SWEP01`, and `userMaterial: true` only. Nodes and checks do not identify printed pages or exact source rule/claim. This is insufficient for the project requirement that evidence specify edition, PDF, printed page, rule/scene, executor, controller/UI path, persistence/reopen, and test. Add claim-level source references before treating individual scenes as evidence-backed.
2. **Adventure coverage is a narrative graph, not a source-complete transcription.** The current graph is 17 nodes. It has broad opening, three hubs, short Umbra/Spyder/Zelcomm variants, abstract NovaCORE routes, parley/showdown, and epilogue, but omits most of the source’s explicit procedures, branches, equipment, interactions, optional encounters, and tactical area rules listed above.
3. **Check options and choices are weakly bound.** `advanceUnderBlackSun` applies any currently available choice immediately and stores its effects. Most choice availability is node/visited-count based, not contingent on rolling the associated check. This allows a player to choose source outcomes without the check/source conditions (e.g. freely obtain the Umbra lead, claim the Zelcomm route, or select the ending). Only Kaa’to parley/capture outcomes have check/encounter conditions. Establish an action contract so each source-dependent effect is emitted by deterministic adjudication, then expose only eligible choices.
4. **Check-pool parser loses source semantics.** `poolForDifficulty` converts difficulty prose with limited regular expressions. Unsupported “variável” becomes Average; bespoke phrase formats can be mistranslated; notably “1 Dificuldade + 1 Desafio” maps to one Difficulty die plus one Challenge die but is not enough to represent all source modifiers. There is no source-page-specific modifier ledger for traffic, guards, approach, cover, machinery, observer count, or named destiny spends.
5. **RAG/narrator boundary:** Current UI says narration must not reroll or decide for the player, and deterministic code owns check resolution, route choice, encounter history, and consequences. Preserve that boundary. RAG may surface only the page text and page citation; it must not set route flags, add Obligation, grant clues/items/credits, change NPC state, trigger optional combat, or resolve Kaa’to. Narrator text is not evidence that any mechanics occurred.
6. **Tests and persistence are not semantic certification.** Static test files prove covered code paths at the asserted level; they do not reconcile the PDF, PC distribution, and combat values. A prior WIP regression run was recorded elsewhere, but this audit did not execute tests. Required closeout evidence remains source-to-effect coverage, focused positive/negative tests, controller/UI path, saved and reopened state, and exact PDF page citation for each rule/branch.
