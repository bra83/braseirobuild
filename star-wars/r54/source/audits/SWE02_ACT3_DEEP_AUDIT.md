# SWE02 Act 3 deep source audit — Mos Shuuta and Teemo's palace

**Date:** 2026-10-16  
**Scope:** *The Long Arm of the Hutt*, official PDF printed pp. 39–46 (physical PDF pp. 40–46); Act 3 return/infiltration, palace rooms and maps, security/combat, alternatives, endings, consequences and rewards.  
**Comparison set:** `work/star-wars/Long Arm of the Hutt.pdf`, extracted text `work/star-wars/long_arm_text.txt`, recovered P244 + cumulative WIP5 source tree `work/star-wars/project`, validation artifacts and existing tests.  
**Method:** read-only source and code inspection. No source code or other audit was edited and no tests were executed for this audit. Existing test files and prior proof artifacts are cited as evidence of asserted coverage, not as a fresh successful test run.  
**Decision rule:** a claim remains **PENDENTE** unless the source page, deterministic executor, controller/UI, persisted state and reopen behavior, and specific test evidence all align with that claim. `PARCIAL` describes implementation that exists but does not close the full source semantics.

## Finding

Act 3 has a useful scene graph and several guarded, durable mechanics: gate checks and disguise, palace-room observations, gladiator recruitment/combat, the throne-room alarm timer, communications checks, evidence-backed peaceful resolutions, a chandelier attack, and the post-victory strongbox. Prior proof artifacts and tests show controller, UI/bridge, validation and save/reopen coverage for selected slices.

This is not an editorially complete Act 3. The return/landing branch and its ship/Imperial conditions are mostly absent; the map is not a tactical model; some official alternatives are omitted or bypassable; and the laser cannon, bar explosion, combat cover, guest/NPC reactions, complete communications consequences, Anatta handoff and 500-credit-per-PC reward, retreat/capture, and aftermath relationships are not all represented as complete player-executable flows. Some prose and declarative observations are recorded as flags without connecting those facts to the official downstream effects.

## Cross-cutting implementation and evidence inventory

### What has controller/UI/persistence evidence

- Generic palace operations: `GameController.swe02PalaceOperationCatalog/executeSWE02PalaceOperation`, bridge methods, and the `swe02PalaceDeclarative` panel are present. Existing whole-zone/declarative tests inspect HTML/UI IDs, atomic rollback, duplicate rejection and three repository reopenings for selected operations.
- Gladiators and alarm: controller/bridge methods and UI controls exist; existing test checks actual credit debit, opposed pool, combat formation, Teemo NPC maneuver, round count, and three reloads.
- Act 3 resolution: controller methods and bridge wiring exist for dossier, peaceful outcome and strongbox; tests cover selected receipts and save/reopen behavior. Chandelier has a real action check and a focused controller test path.
- Palace scene graph nodes are in `longArmOfTheHutt.mjs`; simply navigating among these nodes is not proof that each map position, NPC, or combat modifier is actually simulated.

### Existing evidence does not establish

- Every official branch on pp.39–46, every contingent route or ending, or every source page's full meaning.
- A tactical palace map that supports range, line of sight, cover and move costs.
- Ship-dependent landing/Imperial patrol logic, town return NPC interactions, Vios' landing objection, and conditional Dunelizard content.
- Full combat support for room cover/bar explosion/cannon; B1 crate delivery; guest/servant/house band actions; Thwheek's roam/escape/theft; allied gladiator actions; failure/capture recovery.
- The complete Anatta-to-Jabba delivery and 500-credit-per-PC payment, or source-complete relationship/reputation/aftermath outcomes.
- Fresh test status. This audit only inspected prior proof artifacts and test source.
